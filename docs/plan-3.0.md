# 版本说明 3.0

本文只定范围。3.0 尚未开始，不改变已经发布的 2.3.8。实现前不得修改 `versionCode`、服务端 `Version` 或 schema。

3.0 做三件事：把设置改成两到三级页面；在本机按日整理两人的文字；让 Hermes 只按一份工具清单调用脚本，再用固定格式把结果说出来。助手语音通话已在 2.4.0 从手机去掉。

两人之间的语音和视频通话保持 2.3.7 与 2.3.8 的行为，包括接通顺序、字幕和挂断后的文字记录。点「总结摘要」才生成本次通话纪要，这一点不改。

## 助手语音通话

2.4.0 已在手机上去掉助手通话：不再发起，也不接听 `bot` 为 true 的来电。助手页的语音消息和朗读回复保留。

3.0 若改到 Hermes 适配器，再删除主机上残留的接听代码。在此之前不重启 Hermes。

下列两项取消，不再列为以后要做的功能：

- 双人通话进行中邀请助手。
- 绕过工具、直接使用实时语音模型的助手通话。

## 设置

设置首页只放入口。每一项是一个名称加一行现状，点进去才是原来的开关和输入框。说明放在该页顶部，最多两句。不得在首页展开长段解释。

首页入口按这个顺序：

| 入口 | 第二级 | 第三级 |
|---|---|---|
| 聊天 | 定时销毁；外观与字体；链接与流量；导出 | 外观页内再分主题色、背景、气泡 |
| 通话 | 铃声与免打扰；来电提示；本月统计；文字记录 | 无 |
| 加密与安全 | 加密状态；安全码；密钥；应用锁；防截屏 | 密钥页内再分轮换、迁移、导出、导入 |
| 本机能力 | 语音转文字；整理模型；每日摘要 | 语音转文字页内再分本机模型与云端地址 |
| 助手 | 名字与显示；通知与朗读；快捷指令；工具 | 工具页内再分每一项的说明和开关 |
| 账号 | 密码；登录设备；网页版；离线通知 | 离线通知页内再分渠道、样式、间隔 |
| 关于 | 版本；缓存；诊断 | 无 |

现在散在首页的「端到端加密」「通知与通话」「语音识别」「通话纪要」「安全」「存储与诊断」都收进上表，不另起一套设置项。下载模型的按钮仍只出现在「本机能力」里。打开某一项功能不得开始下载。

## 本机每日摘要

整理仍用手机上已经下载的本机模型。聊天原文、摘要和记忆都不得离开这台手机，不得交给 Hermes，也不得交给云端模型。Hermes 继续只能看见助手页和明确 @ 它的内容。

下载模型不得自动打开每日摘要。用户在「本机能力 → 每日摘要」里打开之后，才按下面的规则运行。关掉之后，已有的摘要留在本机，可以再单独删除。

运行规则：

- 每个自然日最多调用一次模型。当天没有双方的文字消息时，不调用模型，记一行为「这天没有文字消息」。
- 只在应用处于前台、当前没有通话、模型已经就绪时运行。错过的那一天不补跑模型；次日只处理新的一天。
- 输入只取本机已经解密的双方文字，不含助手页，不含通话录音。单日文本过长时从末尾截取，并在摘要里注明前面已略。
- 长期记住的事只从当天摘要里的短句合并进来，不得再把全部历史重读一遍。

每天的结果用固定四行，写进本机记录，默认保留 90 天：

1. 日期。
2. 聊了什么。没有内容就写「这天没有文字消息」。有内容时不超过一百五十字，不得编造。
3. 心情。只允许「平稳」「开心」「担心」「生气」「说不准」。原文不够判断时必须写「说不准」。
4. 可记住的事。最多三条短句。每一条都须能在当天原文里找到。没有则这一行为空。

用户打开「每日摘要」页时，按日期列出这些记录。页面标题就叫「每日摘要」，不使用「超级记忆」「智能分析」一类说法。

## 助手的工具

助手回答「帮我查、帮我办」这类请求时，不得自己搜索、不得读清单以外的文件、不得执行清单以外的命令。它只能多次调用工具清单里的脚本，再按固定格式把结果发回聊天。

工具清单放在 Hermes 主机上，是一份 JSON。手机上的「助手 → 工具」可以查看、排序、启用或停用，也可以改两项给人看的文字：什么时候用、结果怎么说。脚本路径和参数格式只在主机上改，模型改不了这份清单。

每一项至少包含：

- 标识。调用时使用，用户界面不强调它。
- 名称。给用户看的短名。
- 什么时候用。一句人话，供选择工具时阅读。
- 脚本。主机上的路径。适配器执行它，不把外壳交给模型。
- 入参。允许的字段。模型多给的字段须丢弃。
- 出参。脚本成功时 stdout 必须是这些字段组成的 JSON。
- 结果句式。用出参字段填空的一行人话。

一次用户发言的处理顺序：

1. 若是闲聊，且对不上任何工具，只回复一段短文。这段短文不得声称已经查询过。
2. 若是在要一个结果，编排器只从已启用的工具里选择。可以按顺序调用多次。每一次都能看见前面几次的结构化结果。
3. 单次发言最多调用 4 次。到达上限仍缺结果时停止，并说明做到哪一项。
4. 模型只提交工具标识和入参。适配器运行对应脚本，读完 stdout 再决定是否还要下一次。
5. stdout 不是约定的 JSON，或进程失败时，这一项记为失败。聊天里不得贴出原始报错或堆栈。
6. 全部调用结束后，用下面的版式发一条消息，替换掉等待中的那一条。不得先把推理过程流式写进气泡。

有结果时：

```
查到了
（按各次调用的结果句式各写一行，顺序与调用顺序相同）
用了：名称 → 名称
```

没有这项工具时：

```
这个我还做不了
工具里没有对应的一项。
```

脚本失败时：

```
没查成
（名称）没有返回结果。
```

等待过程中，气泡只显示「正在查」。不得出现「Running」「正在思考」「让我搜索一下」这类过程说明。现有适配器已经丢弃的网关状态行继续丢弃。

清单为空，或一句请求对不上任何工具、又不是闲聊时，使用「这个我还做不了」。不得改去网页搜索来补。

## 界面用语

给人看的文字要能直接读懂。一个控件只保留名称和一行现状。

须换掉的说法：

| 现在容易出现的说法 | 3.0 界面用 |
|---|---|
| 端侧大模型、超级记忆 | 每日摘要 |
| 智能体、编排、工具调用 | 工具 |
| Gemma、SenseVoice 作为主标题 | 整理、语音转文字。具体模型名放在该页的第二句 |
| 正在推理、已调用某函数 | 正在查；完成后用上一节的三行版式 |

助手页不再提供通话按钮，也不再把通话状态写进助手的回复。

## 明确不做

- 不改两人通话的接通、打洞、字幕和挂断后的文字记录。
- 不把每日摘要或工具结果自动发成一条聊天消息。用户若要发给对方，须另有一次明确的发送动作。
- 不增加消息 `kind`。工具清单不进入两人的加密会话。启用状态若要双方一致，实现时再决定是用现有共享配置，还是只保存在 Hermes 主机上。本文不因此提升 schema。
- 不把网页版做成助手或通话客户端。
- 不做主题预设，也不做助手页底栏。
- 不改高德瓦片，也不引入虚拟网卡。

## 实现顺序

按下面的顺序做，每一段都可以单独装到手机上验证：

1. 把设置收成上表的两到三级，不改各项原来的保存位置。
2. 加上每日摘要的开关、本地记录和固定四行。
3. 最后改 Hermes：工具清单、最多四次调用、固定三行回复。适配器行为变了才需要重启 Hermes。若同时删除主机上残留的助手接听代码，也在这一步。
