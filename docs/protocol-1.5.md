# 协议增量 1.5.0

相对 [protocol-1.3.md](protocol-1.3.md)。schema 保持为 7。

## 1. 限流

每个连接使用两个令牌桶：帧速率 40 次/秒，突发 80；`msg.send` 为 60 次/分钟，突发 90。助手连接的限额为人类连接的 3 倍。超出时返回 `error{code:"rate_limited", ref?}` 并丢弃该帧。连续 10 秒超过帧速率上限则断开连接。

## 2. 未被引用的媒体

上传后超过 `CHATTER_MEDIA_GRACE_SECONDS`（默认 7200 秒），且没有任何消息将其用作 `media_id` 或缩略图 `thumb_id` 的媒体行与文件，由清理循环删除。循环间隔为 `clamp(grace/2, 2, 600)` 秒，默认约 10 分钟。

## 3. kind `location`

人类用户可以发送，也可以 `to:"bot"`（明文）。`text` 最长 512 字符，格式为 `lat,lng|精度米|地址|live`。`live` 为 `1` 表示实时共享仍在进行。人类之间的 `text` 为 `e2e:` 或 `e2e2:` 密文。摘要为 `[位置] 地址`。该 `kind` 属于内容消息。

`edit` 可以作用于 `location`。实时位置约每 10 秒编辑同一条消息，15 分钟后的最后一次编辑将 `live` 置为 `0`。客户端对 `location` 的编辑不显示「已编辑」。

## 4. 通话

`call.media` 增加可选字段 `screen`（布尔），表示发送方开始或停止共享屏幕。视频通话中，屏幕共享复用摄像头轨道，不重新协商。语音通话中，新增一条视频轨道并重新发送 offer。

## 5. 密钥

- `POST /keys` 的 `pubKey` 上限由 512 调整为 4096 个字符。服务端仍不解析该字符串。
- 1.5 客户端发布的是 v2 bundle：`v2|<身份公钥>|<n>|<第 n 期公钥>|<签名>|<n-1>|...`。最多保留最近 12 期，新的在前。签名为身份私钥对 `"lochatter-epoch|" + n + "|" + 公钥` 做 ECDSA-SHA256。旧客户端发布的裸 X.509 公钥仍接受，视为第 0 期。
- 会话密钥（发送方 A 的第 a 期，接收方 B 的第 b 期）为 `HKDF-SHA256(ECDH(A_a, B_b), salt = SHA-256(sorted(pub_a, pub_b)), info = "lochatter-e2e-v2|a.b")`。任一方为第 0 期时退回 v1，使用身份密钥。约每 7 日轮换一次。安全码只由身份公钥决定，轮换不改变安全码。
- 文本密文 v2：`e2e2:<发送方 uid>:<a>.<b>:<base64(nonce‖ct)>`。媒体 v2：`LCE2` ‖ uid(8) ‖ a(4) ‖ b(4) ‖ `LCE1` 正文。接收方根据 uid 判断自己是发送方还是接收方，再从密钥环取出对应两期的密钥。旧的 `e2e:` 与 `LCE1` 仍可解密。
- 迁移：原设备在设置中生成二维码。内容为以 PBKDF2（6 位 PIN）导出密钥、再用 AES-GCM 封装的密钥环 JSON，并含服务器地址与令牌。新设备扫码并输入 PIN 后重新同步历史。

## 6. 助手

`POST /bot/card {text}` 仅接受助手令牌。服务端插入一条 `card` 消息并广播。运维脚本用它报告服务恢复。

助手收到的 `location` 在插件侧转换为 `[位置] 地址 (lat,lng，精度 N 米)`。
