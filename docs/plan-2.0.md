# 2.0 开发计划：助手语音通话

更新于 2026-09-23。当前稳定版本为 Android 1.9.1；服务端 1.9.0。2.0 聚焦「直接和助手说话」，不把语音通话的媒体中继放到聊天服务器上。

## 目标

- 在 Android 通话界面里直接与 Hermes 助手进行语音对话，不必先录制、发送语音条。
- 全双工：用户可在助手播放时插话；助手停止当前 TTS 并中断当前处理，优先处理新输入。
- 通话期间显示双方字幕，并区分用户转写与助手正在说/已说内容。
- 网络或模型服务异常时清晰降级，不丢失用户已说内容，不让通话界面卡死。

不纳入 2.0：助手加入两个人的实时通话、通话记忆、实时 speech-to-speech 模型。这些分别属于 2.1/2.2。

## 端到端链路

手机 WebRTC Opus 音频 → 跑助手的那台机器上的 Hermes 插件（aiortc）→ VAD 分段 → 模型服务转写 → Hermes 现有 Agent 流程 → 按句切分并请求语音合成 → Opus 音频回手机。那台机器只做音频收发、编解码和 VAD；识别、Agent 推理与合成在模型服务上完成。模型名用那边实际提供的，不要猜。字幕用新增的 `call.caption` 信令帧传递，音频媒体仍经 WebRTC P2P/TURN，不走聊天 WebSocket。

## 分阶段交付

### 2.0-alpha：对讲链路验证

- 暂不实现全双工；用现有语音条/助手接口验证 NAS 插件、hub 转写、Hermes 回复、TTS 合成与手机播放的整条链路。
- 固定一轮请求/响应，记录每段耗时、音频格式、失败原因和资源占用；确认中文、静音、短句、长句均可工作。
- 首次开口目标约 3 秒；通过短开场句将可感知首响压到约 2 秒。该指标作为优化目标，需以实际模型首包数据确认。
- 通过条件：连续 20 轮成功；失败可重试且不会重复触发 Agent 回复；中断/断网后进程和连接可恢复。

### 2.0：全双工与字幕

- 助手作为 WebRTC 对端加入现有通话状态机，建立音频轨与助手呼叫/挂断生命周期。
- 加入 VAD 打断：助手播放时检测到用户语音，立即停播、取消未播放 TTS 队列并向 Hermes 发出中断；新一轮转写作为后续输入。
- 增加 `call.caption`：包含 call id、说话方、文本、时间戳和片段状态（partial/final）；校验呼叫归属，忽略过期 call id 的帧。
- 通话 UI 展示滚动字幕、连接/处理/朗读状态、静音、挂断和重试；字幕不覆盖既有视频/屏幕共享控件。
- 通话结束清理 VAD、音轨、字幕队列、TTS 请求和 NAS 会话；旧会话迟到的数据不得串入新会话。

### 2.0.1：稳定性与降级

- 覆盖 ICE 重连、Wi-Fi/蜂窝切换、TURN 中继、高延迟、弱网、权限撤销、后台/锁屏恢复。
- hub 转写或 TTS 超时可提示并重试；单项服务不可用时提供文字/语音条回退入口，不静默吞掉输入。
- 设定队列上限与背压，避免用户连续插话导致音频、转写和 TTS 队列无限增长。
- 补充端到端延迟、丢包、重连次数和服务错误的诊断信息；不记录原始音频或敏感转写到常规日志。
- 发版前确认 VPS 与 NAS 的实时资源占用，确认通话媒体未经过 VPS。

## 开始开发前的验证

1. 实测 hub 是否代理 `/v1/audio/transcriptions`，包括文件格式、鉴权、中文识别和最大时长。
2. 实测 `/v1/audio/speech` 的流式响应、首包时间、音频编码及取消请求是否能及时停止生成。
3. 向模型服务查实际可用的转写和合成模型标识、限流、超时和费用；不要把模型名或接口行为凭配置猜测。
4. 在跑助手的机器上压测 aiortc + Opus + VAD，记录 CPU、内存、温度和长时间运行情况。
5. 设计 Hermes 中断 API 的幂等行为，保证连续插话或重连时不会误停下一轮任务。

任何关键前提未通过，都先完成 alpha 的替代链路或调整范围，不直接进入全双工开发。

## 头像切换：现状与验收

头像切换不是全新待开发项：1.8 已有资料页选图、压缩上传、加密共享 media id、双方同步，聊天列表/顶栏/「我」页展示也已接通。2.0 保留该能力，不另建头像协议。

本次先修复登出时共享资料派生状态未完整清空的问题。2.0 回归时验证：

- 资料页选择图片后，资料页、聊天顶栏、聊天列表和「我」页均更新；另一台手机收到更新。
- 选图取消或上传失败时保留旧头像；更换后重启、离线再上线仍显示正确头像。
- 登出后内存中的头像、签名、置顶状态归零；重新登录只恢复新账号/会话的共享资料。
- 当前头像在对方关闭摄像头等语音/视频通话占位态中的展示可作为 UI 改进项；不阻挡语音通话主链路。

## 验收与发布

- 自动化：服务端协议/鉴权测试、Android JVM 单元测试；为 `call.caption` 编解码、call id 过滤、乱序/迟到字幕、打断取消和共享资料清理增加测试。
- 手动：两台真机，一台 Android 12；P2P 与 TURN 各跑一遍；连续插话、静音、后台恢复、切网、hub 失败均覆盖。
- 性能：记录用户停顿到字幕、字幕到首段语音、插话到助手停止三项延迟；记录 NAS/VPS 峰值资源。
- 按仓库发版流程执行 `bash tools/check.sh --e2e`、Android release 构建、双机回归，并保留服务端/APK/Hermes 插件回滚点。
