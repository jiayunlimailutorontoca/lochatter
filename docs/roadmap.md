## 1. 发版前真机回归清单（1.6.0 起每版都过）

1.3.0 和 1.5.0 都只跑了服务端 e2e、本机编译、单元测试，没有在手机上点过；1.5.0 上线后就因此漏了「位置发不出去」。每版装到两台手机（其中一台 Android 12）按下面过一遍：

- 升级路径：从 1.2 / 1.3 直接装 1.5，登录状态、密钥、聊天记录都还在（1.5 把令牌和私钥从旧的加密库迁到了 Keystore 加密的新库）。
- 助手：连发三问并按停止，每问最多一条回复；Hermes 重启期间提问，重连后有回复；「/」菜单、快捷指令、朗读、开车模式、点麦克风说话。
- 表情面板、自定义收藏两人同步；拍一拍；收藏；图片与文件；语音转文字（以及手机识别不了时交给助手）；链接预览；定时发送（锁屏后）；阅后即焚；纪念日提示；电量；外观；免打扰；铃声；小组件。
- 通话：表情浮层、一起画（TURN 中转下）、共享屏幕（视频通话里切换，语音通话里新增视频轨；Android 14 上前台服务类型）、本月统计。
- 1.5 新增：位置分享（没有 Google 服务的机型地址可能为空，只显示经纬度）、实时位置 15 分钟、语音倍速和拖动、连播、图片编辑（画笔 / 马赛克 / 裁剪）、完整表情回应、导出 zip、二维码换机、密钥轮换（两台都升到 1.5 后一周内自动换第一期；设置里能看到期数）。
- R8：1.5 开了代码压缩（不混淆）。重点看 WebRTC 通话、序列化（登录 / 收发消息）、Coil GIF 有没有因为被裁掉类而崩；崩溃会记录在「导出诊断信息」里。

## 2. 1.9：结构与网页端（已做）

- `ChatRepository` 拆成 `MessageRepository` / `BotRepository` / `SharedStore` / `MediaUploader`。拆之前先有 JVM 测试：消息应用、去重、解密回退（`MessagePipeline`）。
- 网页端雏形：`https://chat.example.com/web/`，同一协议，只做文字 + 图片。WebCrypto 做 e2e v2，密钥用手机上的换机二维码迁过来。浏览器的 WebSocket 用 cookie `chatter` 带同一条令牌（见 `docs/protocol-1.9.md`）。
- 语音通话的音频不要从聊天服务器中转。转写和朗读走单独的模型服务，媒体留在手机和跑助手的那台机器之间。

## 3. 2.0：和助手打语音电话

（设计不变，见 1.3.0 时写的版本，摘要如下。）

助手作为 WebRTC 的一端：手机 Opus → 跑助手的那台机器上的 Hermes 插件（aiortc）→ VAD 切段 → 模型服务转写 → Hermes 正常处理 → 按句合成语音 → Opus 回手机。模型名用那台服务实际列出的，不要自己猜。打断靠 VAD：播放时检测到人声就停播，并让 Hermes 停下当前这轮。字幕走 `call.caption`。聊天服务器不转发音频。首次开口大约 3 秒，先说短句可以再短一点；这是目标，要以实测首包为准。

分三步：2.0-alpha 对讲式（不动 WebRTC，用现有语音条往返验证链路）→ 2.0 全双工 + 字幕 + 通话页适配 → 2.0.1 稳定性（ICE 重连、TURN 延迟、hub 超时降级）。

前提要核实：模型服务是否提供 `/v1/audio/transcriptions` 和流式 `/v1/audio/speech`，以及合成的首包要多久。
